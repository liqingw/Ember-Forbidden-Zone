# 更新日志

## v1.4.4 修复普通关卡清空后没有传送门（卡关）（当前）

### 修复

- 修复「普通关卡打完后给了钥匙却没有传送门」：此前只有**首领房**才会生成传送门，普通层清空房间只解锁房门。
- 而传送门是通往下一层的**唯一**出口 —— 于是普通层玩家清光所有房间后仍被永久困在同一层（软锁死），只能重开。
- 现在每层都会记录一个「目标房」（初始点距离最远的那间），清空它即出现传送门，与首领层的规则保持一致。

## v1.4.3 修复 PC 端键盘完全没有反应

### 修复

- **「人物钉死、键盘操控完全无反应」** —— 在个别机器 / 窗口管理器下，
  游戏窗口会被系统判定为"未聚焦"，此时键盘状态表会**整张恒返回"没按"**，
  于是无论怎么按键都读不到输入，人物一动不动；
  但画面上敌人、子弹仍在正常运动，看起来就像"卡死了"。
  现在改为**双通道读取**：除了键盘状态表，还额外用按键事件累积一份
  "当前按住的键"，两者取并集。只要按键事件能到达，角色就能移动 ——
  从根上绕开窗口焦点问题。
- **窗口失焦时清空按键集合**，避免"松了手角色还在自己走"。
- **防幽灵按键**：键盘状态表正常却报告"全都没按"、而事件集合仍有按键时，
  持续 0.5 秒即判定丢键并清空，避免黏键。

### 诊断增强

- 首次收到移动输入会写一行到 `boot.log`，
  可用于区分"输入根本没到达"还是"输入到了但走不动"。

### 测试

- 新增 Python `T23` / 网页 `W24` 两个**真实键盘输入路径**回归用例。
  此前全套用例都用 `inp_override` 注入输入，会**完全跳过**键盘状态表的读取，
  导致这类 bug 测试完全无感。

## v1.4.2 网页端全面对齐 + 移动手感修复

### 修复

- **打击停顿（hit-stop）把玩家也一起冻住** —— 表现为"连续命中时几乎无法移动"。
  根因：打击停顿期间把缩放过的时间步长 `wdt` 也作用到了玩家身上，
  高射速武器 / 多个敌人时每帧都在命中，`wdt` 被长期锁死在 6%。
  现在**只冻结世界**（敌人 / 子弹 / 陷阱 / 掉落物），
  **玩家的移动与瞄准永远按真实时间步长走**。
- **打击停顿加入冷却**（`HITSTOP_COOLDOWN = 0.09s`），
  并把世界时间缩放比从 0.06 调到 0.35，避免"又顿又粘"。

### 网页端全面对齐（此前与本地版内容不一致）

- **完整存档系统**：3 个存档槽 + 个人 ID + 自动保存，
  与 PC 端 `save.py` 字段结构完全同构（浏览器侧落在 `localStorage`）。
- **选档界面**：开始游戏 → 选档 / 新建 / 删除（含不可逆操作的二次确认）。
- **分档设置**：音乐 / 音效 / 震动 / 摇杆模式与灵敏度**随档保存**，各档独立。
- **进度持久化**：场景进度、图鉴、收集品、展示台、货币、材料全部落档。
- **程序合成 BGM**：纯 WebAudio 现场合成，默认关闭，
  曲目按场景深度分 4 档（越深越低沉紧张）。
- **断点续玩**：从存档里的关卡断点继续，而不是每次都从第 1 关开始。

## v1.3.1

### 修复

- **桌面版双击后长时间无反应（最严重）**
  根因是启动时调用了 `pygame.init()`，它会顺带初始化 **手柄子系统**。
  Windows 上 SDL 枚举 HID 设备时，本机被测出要阻塞 **整整 60 秒**
  （`joystick.init()` 单项耗时 60.2s）。而这发生在**创建窗口之前**，
  于是双击 exe 后一分钟内屏幕上什么都没有，看起来就像"打不开"。
  更麻烦的是 `--selfcheck` 走的是 SDL dummy 驱动、根本不初始化手柄，
  自检永远 PASS，完全掩盖了这个问题。

  现在改为**手动按需初始化** display / font / mixer 三个子系统，
  显式跳过 joystick。**实测启动耗时 60.7s → 1.0s。**
  顺带加了启动闪屏与 `boot.log`，以后任何启动问题都有现场可查。

- **鼠标不在最上层**：准星原本画在 640×360 的逻辑画布上再被整体放大
  2~3 倍，又糊又粗；且系统箭头未隐藏，压在准星上挡住瞄准点。
  改为直接在缩放后的窗口层绘制（线宽恒为 1px）并隐藏系统光标，
  退出时恢复。全屏切换后也会重新隐藏（`set_mode` 会重置光标状态）。

- **天赋界面空指针崩溃**：`pending_talents` 为空时仍按 `len(picks)` 循环
  取 `picks[0]`，抛 `IndexError`。已加空表兜底（两端同步修复）。

### 界面

- **重排拥挤的 HUD 与客厅**（用户反馈"操作界面很拥挤，排列不当"）：
  - 右上资源全部改为**右对齐**，金币四位数时不再顶出屏幕；
  - 左上能量条宽度改为随红心数量伸缩，数字紧跟条尾，
    不再与中间的场景横幅重叠；
  - 房间名（y=62）与场景名（y=44）拆成两行，各自避开右上角资源区；
  - 客厅标题与面板描边分离（面板下移到 y=26），TAB 分页条移入面板内部；
  - 图鉴页码不再压在列表最后一行；
  - 交互提示框会自动避开左下武器面板；
  - 展示台描述行与格子分离。

### 测试

- Python 232/232、数据层 380/380、网页版 268/268 全绿。
- 新增 `tools/startup_probe.py`：用**真实**视频驱动跑完整启动管线并逐步打点。
  这是发现 60 秒阻塞的关键——原有 `--selfcheck` 因为走 dummy 驱动而看不见。
- 新增 `tools/probe_init_isect.py` / `tools/probe_joystick.py`：逐子系统计时定位。

## v1.0

### 剧情与关卡

- 主线叙事：污染入侵 → 生存。7 个主题场景、35 关（4 主线 + 2 副本 + 1 奖励副本），
  每个场景 5 关、每关 3 个房间。
- 每种场景有独立的色调、敌人配比与机制。

### 场景建模

- **陷阱**：地刺、酸池、电弧等，按场景投放。
- **掩体**：石柱 / 方块，可挡子弹、可绕后。
- **奖励洞穴**：藏在房间角落，含宝箱或大量金币。

### 系统

- **货币**：金币易得、钻石难得（首领必掉）。
- **材料**：8 种材料，掉落与场景相关。
- **角色**：新增 5 个可选角色，各自初始属性与武器倾向不同。
- **武器品质**：7 档，从学徒手枪到金色传说炮。
- **图鉴**：怪物 / 武器 / 材料 / 收集品四类，遇到即收录。
- **收集品展示台**：6 格，可自由取出放回。
- **存档**：3 槽位，按角色名隔离。
- **防卡死**：连续零位移自动脱困；每关自动存档。
- **客厅二级界面**：关卡地图 + 图鉴 + 展示台三分页。

### 表现

- 音乐 / 音效 / 屏幕震动（默认关闭，可在主菜单开启）。
- 局内文字提示系统（toast）。
- **三端同构**：PC 桌面版、网页单文件版、手机 PWA 版共用同一套逻辑与数据。

## 技术说明

- 逻辑与渲染：Python 3.13 + pygame-ce（PC 版）；HTML5 Canvas（网页 / 手机版）
- 双端逻辑镜像：`src/sk/*.py` 与 `web_src/game.js`

- 无头自动化测试三套：
  - Python 逻辑：`tools/selftest.py`
  - 数据层：`tools/test_data.py`
  - 网页版：`tools/web_selftest.js`
